# ResNet-20 RTL-Lock Quantization Contract Review

This document records the R0.5 F6a review for rounding, saturation, and
requantization semantics before ResNet-20 fixed-point assets are handed to RTL.
It does not start RTL R1 and does not generate memh files, task sequences, or a
`1 MB` memory reuse map.

## 3. Contract Comparison

Reviewed matching items:

- `round_half_away_from_zero`: matches existing RTL and LeNet software contract.
- `round_shift_half_away`: matches RTL absolute-product rounding bias and sign restore.
- `requantize_int64`: matches the existing multiplier/shift primitive for positive multipliers and shifts in `0..31`.
- INT8 saturation: matches signed INT8 clamp range `[-128,127]`.
- F3 multiplier/shift constraints: compatible with current `task_checker` limits.

Open items:

- Folded bias INT32 rounding uses half-away software export rounding, but there is no current ResNet bias export/RTL consumption path to lock yet.
- GAP reciprocal/shift is planned in software, but there is no current ResNet GAP RTL datapath to compare.
- Residual ADD same-scale branch alignment uses the same requant primitive in software, but the future ADD datapath has not been implemented or RTL-locked.

## 5. Decision

No mismatch was found in the existing LeNet/NPU requant primitive contract.
However, the review is not `reviewed_match` because ResNet-specific folded bias,
GAP, and residual ADD datapath handoff details still need RTL-owner lock.

Current decision:

```text
rtl_lock_status = reviewed_with_open_items
next_allowed_stage = resolve_open_items_or_waiver
```

In practical terms, this means INT8/INT32 export should not be treated as fully
unblocked until the open items above are resolved or explicitly waived. RTL R1
remains not started.
